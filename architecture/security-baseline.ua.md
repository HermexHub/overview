# 🛡️ Базові стандарти безпеки Hermex
### Безпека додатків (AppSec), захист від загроз OWASP та відповідність PCI-DSS

Цей документ описує практики інформаційної безпеки (AppSec), захисту платіжних даних (PCI-DSS) та запобігання поширеним вразливостям (OWASP Top-10), реалізовані в платформі Hermex.

---

## 🔒 1. Захист від перебору облікових записів (OWASP Anti-Enumeration / CWE-204)

- **Знеособлені відповіді авторизації:**  
  При помилках входу або реєстрації сервер завжди повертає єдиний статус `401 Unauthorized` із повідомленням `Invalid email or password`.
- **Конфіденційність статусу акаунту:**  
  Система ніколи не повертає повідомлень штибу *«Користувача не знайдено»* чи *«Невірний пароль»*, що унеможливлює збір бази валідних адрес зловмисниками.

---

## ⏱️ 2. Захист від атак за часом (Anti-Timing Attacks)

- Час відповіді сервера не повинен викривати наявність адреси користувача в базі даних.
- **DUMMY_HASH:** Якщо email відсутній у `gateway_db`, сервіс автентифікації виконує реальне обчислення `bcrypt.compare` з фіктивним валідним хешем:
  ```typescript
  const DUMMY_HASH = '$2b$10$abcdefghijklmnopqrstuvABCDEFGHIJKLMNOPQRSTUV0123456789';
  await bcrypt.compare(password, user ? user.passwordHash : DUMMY_HASH);
  ```
  Це гарантує постійний час виконання (Constant Time Execution) криптографічної операції незалежно від наявності користувача в БД.

---

## 🎭 3. Маскування внутрішніх деталей помилок (CWE-209 Error Masking)

- **Глобальний фільтр винятків (`GlobalExceptionFilter`):**  
  У продакшен-середовищі клієнтам суворо заборонено передавати стек-трейси, внутрішні назви таблиць, SQL-запити або дампи RPC-викликів.
- При виникненні 5xx збоїв клієнт отримує знеособлений JSON:
  ```json
  {
    "statusCode": 500,
    "message": "Internal server error",
    "timestamp": "2026-09-22T12:00:00.000Z",
    "traceId": "c3b95a8e-5b12-421b-bf8d-d3c26725ea94"
  }
  ```
- Повний стек-трейс помилки зберігається виключно у внутрішньому лозі сервера з прив'язкою до `traceId`.

---

## 💳 4. Відповідність стандарту PCI-DSS (Zero Raw Card Storage)

1. **Заборона збереження CVV:** Коди перевірки картки (`CVV` / `CVC`) ніколи не записуються на диск і не зберігаються в жодній базі даних.
2. **Маскування логів (PCI-DSS Redaction):** Бібліотека логування `HermexLogger` (Pino) містить вбудований перехоплювач чутливих ключів:
   - `password`, `refreshToken`, `cvv`, `cardNumber`, `pan`, `pin`.
   Значення автоматично замінюються на `[REDACTED]`.
3. **Ізольований мікрофронтенд оплати (`payment-portal`):** Введення платіжних даних фізично винесене за межі основного магазину (`website`), мінімізуючи контур аудиту PCI-DSS.

---

## 🔄 5. Stateless відкликання токенів та версіонування

- **Двотокенова схема:** Короткоживучий `accessToken` (JWT, 15 хвилин) та захищений HttpOnly Cookie `refreshToken` (7 днів).
- **Колонка `token_version` у `UserEntity`:**  
  Замість збереження великих таблиць активних токенів у БД, сутність користувача зберігає числову версію `token_version`.
- При виклику `/logout`, зміні пароля або ротації токена значення `token_version` атомарно інкрементується, миттєво анулюючи всі видані раніше токени без сторонніх кешів.

---

## 🧱 6. Захист периметра API Gateway

- **Заголовки безпеки Helmet:** Захист від MIME-sniffing (`X-Content-Type-Options: nosniff`), Clickjacking (`X-Frame-Options: SAMEORIGIN`) та приховування сигнатури сервера (`X-Powered-By`).
- **Наскрізна трасування `x-correlation-id`:** Генерація UUIDv4 для кожного вхідного HTTP-запиту з обов'язковим прокиданням у заголовки gRPC та повідомлення AMQP RabbitMQ.
